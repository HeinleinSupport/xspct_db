# Contributing

## Commit messages

Starting with the release **after `0.7.5`**, this project uses
[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/) for
all commit messages. Commits made before that cutover follow an older,
informal `[Tag] Description` convention and have **not** been rewritten
retroactively — see `docs/changelog.md` for the marked cutover point.

### Format

```
<type>(<scope>): <description>

[optional body]

[optional footer(s)]
```

### Types

| Type | When to use |
|------|-------------|
| `feat` | New functionality |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `refactor` | Restructuring without behavior change |
| `test` | Test-only change |
| `perf` | Performance improvement |
| `build` | Build system, dependencies, `pyproject.toml` |
| `ci` | CI configuration |
| `chore` | Other maintenance |

### Scopes

| Scope | Area |
|-------|------|
| `api` | HTTP endpoints, request/response formats (`routes.py`, `schemas.py`) |
| `backends` | LDAP / MySQL / YAML / dummy backends and the dispatcher |
| `cache` | L1 in-process cache, L2 Redis cache, response cache |
| `config` | Configuration schema and defaults |
| `latency` | Latency tracing, percentiles, anomaly detection |
| `metrics` | Prometheus export and stats counters |
| `prefilter` | Address prefilter (domain set, username patterns) |
| `rewrite` | Address rewrite rules |

Omit the scope for `ci` / `build` / `docs` / `test` / `chore` changes that
don't target one of these areas, and for changes that genuinely cut across
most of them.

### Breaking changes

Mark with `!` after the scope (e.g. `feat(api)!: ...`) and/or a
`BREAKING CHANGE:` footer.

### Rules

- Description in the imperative mood, lowercase, no trailing period.
- First line at most 72 characters.
- Body is optional, separated from the header by a blank line.
- **All commits and tags must be GPG-signed:**
  ```bash
  git commit -S -m "feat(api): add msgpack response encoding"
  git tag -s X.Y.Z -m "Tag message"
  ```
- **Never** include "generated by", "co-authored by", or any AI attribution
  in commit messages.
- Independent changes are committed separately — don't mix a backend change
  with an API change in the same commit.

## Code conventions

- **License header** on every source file, lines 1–2:
  ```python
  # SPDX-License-Identifier: EUPL-1.2
  # SPDX-FileCopyrightText: <year> Carsten Rosenberg <c.rosenberg@heinlein-support.de>
  ```
- **Version** is kept in sync between `pyproject.toml` (`version = "x.y.z"`)
  and `src/xspct_db/__init__.py` (`__version__ = "x.y.z"`).
- **Async**: all I/O uses `async`/`await`; tests use `pytest-asyncio`
  (`asyncio_mode = "auto"`). Never add blocking I/O.
- **New backends** subclass `backends.base.BaseBackend`; copy `dummy.py` as
  the minimal skeleton.
- **Test email addresses** must use `@mailexample.de`.

## Before committing

```bash
ruff format src/ tests/
ruff check src/ tests/
reuse lint
pytest
```

CI runs the same checks against Python 3.10–3.12, plus `pip-audit`, CodeQL,
and a dependency licence review. The `ruff` version is pinned in
`.github/workflows/ci.yml`; keep a local install at the same version to avoid
surprises between a green local run and a red CI run.
